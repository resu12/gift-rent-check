# Gift Rent Check v0.4.0

**Development / invitation-only beta — mark this GitHub release as a prerelease.**

This release makes rental management clearer and reduces Telegram storage growth. It includes the gift-refresh progress fix deployed as revision 103. Publishing this source release does not open registration or reset a deployment.

## Highlights

- **Clearer Status:** see which gifts, prices, comparison averages and analytics reports were checked, when they were checked, and what needs attention. Wallet, Marketapp login and API-key controls are grouped under Connections.
- **Easier gift management:** Simple and Detailed views, remembered sorting, last-rented order by default, remaining-rent countdowns, tap-to-copy recommendations and direct Marketapp links. Saved price changes include rental performance before and after each change.
- **Convenient refresh:** pull down to refresh in Telegram. Bounded opening checks can refresh known gifts, remembered-login analytics and eligible comparison data. Additional TON checks now show their own progress instead of leaving a completed Marketapp page at 99%; cooldowns clearly show waiting or paused states.
- **More useful analytics:** press or drag across chart bars for the period, rental count and one-decimal volume. Monthly and annual reports retain their own capture dates and coverage.
- **Invited accounts:** each user verifies their own wallet and supplies their own encrypted API key. Portfolios, credentials, discovery and saved evidence are account-scoped, with export and confirmed deletion controls.
- **Smaller storage footprint:** repeated structured evidence is stored once per account generation, with exact dated observations retained. Superseded operational snapshots retire automatically; resumable scans and the newest 20 terminal scan bodies remain. Cleanup is bounded and resumable, with stable buttons and storage-growth monitoring.

Recommendations retain valid older model/backdrop metadata, cached data keeps its original dates, and missing values remain visible. Account and credential fences reject late writes after deletion or revocation. Request limits, replay protection and encryption nonce counters are preserved.

## Upgrade an existing Telegram deployment

Use the deployment's existing private configuration and encryption key. Back up the database and key, pause collection, install locked dependencies, and run backend/frontend tests, TypeScript, the Telegram build and preflight before publishing. Follow [the deployment guide](https://github.com/resu12/gift-rent-check/blob/v0.4.0/docs/telegram-serverless.md) for configuration and build commands.

Invitation settings now belong in the Git-ignored `serverless/tgcloud/lib/public-release-config.js`. Setup preserves an existing file and otherwise creates it from the disabled `serverless/public-release-config.example.js`; configure the deployment locally and keep its invitation list out of Git.

Apply these steps in order, using the intended app and owner IDs:

1. Publish the additive schema, inspect the migration plan, then apply the safe migration:

   ```powershell
   node serverless/tools/manage.mjs --action publish-schema --app-id YOUR_APP_ID
   node serverless/tools/manage.mjs --action migrate-check --app-id YOUR_APP_ID
   node serverless/tools/manage.mjs --action migrate-safe --app-id YOUR_APP_ID
   ```

2. Install compact-storage accounting, then normalized-record and operational triggers. The setup tool enforces this order:

   ```powershell
   node serverless/tools/compact-storage.mjs --app-id YOUR_APP_ID --owner-id YOUR_OWNER_ID --action setup
   ```

3. Publish the tested runtime and assets:

   ```powershell
   node serverless/tools/manage.mjs --action publish --app-id YOUR_APP_ID
   ```

Existing legacy accounts remain readable. Fresh accounts use compact storage when the required triggers are present. **Publication does not automatically convert or erase existing account history.** Do not roll back to an older writer over compact accounts. The legacy private-owner copy tool refuses compact sources.

### Optional development reset

Only use this for an explicitly approved disposable development dataset. It removes old comparison history, owned price/status observations and scan progress. It preserves credentials, wallet settings, portfolio and traits, analytics reports, request ledgers, nonce counters and monotonic IDs. Rebuild comparisons and gift observations afterwards.

After the upgrade above, call `compact-storage.mjs --action reset` with explicit `--app-id`, `--owner-id`, `--scope private` or `public:USER_ID`, and a fresh `--reset-id dev-reset:UUID`. Continue with `--action dispose`, the same reset ID/scope, the returned `--floor`, public `--generation` where applicable, and successive `--after` cursors until `complete: true`. Retry an uncertain reset using the same ID. Disposal is bounded and makes no provider requests. See [the storage plan](https://github.com/resu12/gift-rent-check/blob/v0.4.0/docs/development-storage-plan.md) for the full procedure and preservation rules.

## Validation

Validated locally with Python 3.12 and Node.js 24: 1,313 Python tests, 1,099 backend tests (two intentional skips), and 724 frontend tests passed. A source-only copy installed both frozen dependency lockfiles and passed backend/frontend tests, TypeScript checks and both dashboard builds without private deployment configuration. The release index excludes local credentials, invitation settings, databases and generated assets. GitHub Actions must still pass on the pushed commit.

## Beta limits

- Open registration remains disabled. Each user's API key still shares the deployment's hosting and provider safeguards.
- Marketapp's website integration is undocumented and available only to the preserved private owner. Invited users use TON gift checks and API-key comparisons; their website login and analytics refresh remain disabled.
- Storage figures measure logical payloads, not the complete physical database quota. Public launch still requires verified hosting capacity, backup/recovery validation and provider/operator review.
- Provider cooldowns, incomplete evidence and interrupted foreground sessions can pause work. The app does not promise continuous collection while closed, execute transactions or change rental prices automatically.
