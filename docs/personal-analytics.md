# Personal rental analytics

Overview can show a saved snapshot of your own Marketapp rental analytics. This is separate from the gift-price recommendation samples and public NFT history. Importing analytics does not alter portfolio membership, asking prices, recommendations, or provider request counters.

The main view shows the selected report's UTC dates, capture age, rent volume before fees and rental count including extensions. **More statistics** expands daily price, average duration, extensions, spending and the period breakdown table. Chart grouping and reporting-period selection use saved data; they do not start a refresh.

Telegram uses one **Report period** selector and a **Refresh** button above the totals. Both **Last 30 days** and **Last 1 year** are available before their first refresh; a period with no saved report shows an empty view rather than another period's figures. Your selected period stays selected when a new capture loads.

**Recently refreshed** means the displayed report was captured less than 15 minutes ago and includes today's UTC date. It is a saved snapshot, not live data; today can still be incomplete. **Update available** identifies an older supported report. Other imported periods show **Saved report**, with their capture time. A fresh annual report does not mark an older monthly report as refreshed. During an update, previous figures remain visible; **Loading refreshed report** and **Older data shown** distinguish a saved result from one actually loaded in the view. **Reload saved data** reads the app's stored report without contacting Marketapp. Age labels update locally while the app is open.

## Refresh in Telegram

The optional remembered login is also reused by the private owner's automatic **known-gift refresh**. It reads personal My NFTs asking prices and rental status; missing details and exact expiry use targeted TON checks. This is separate from analytics refresh and comparison collection. Gift checks can fall back to the saved wallet without a wallet approval or active wallet-app connection. Analytics and personal gift reads share a durable website request allowance and lease. See [known-gift refresh safeguards](telegram-serverless.md#refreshing-your-saved-gifts).

In the private Telegram app, open **Overview**, select **Last 30 days** or **Last 1 year** in **Report period**, then press **Refresh**. Choose your wallet and approve Marketapp's login request if requested. The app signs in for this refresh, reads all-collection analytics with daily grouping, and saves the validated snapshot. It shows the capture time; reporting-period and chart-grouping switches read saved data only.

Expand **Marketapp connection** and select **Remember Marketapp login** before approving to reuse the website session on later refreshes and Mini App openings. The option starts unchecked, and the approval message states whether login will be remembered. The backend keeps only an encrypted, owner-and-wallet-bound session cookie, for at most seven days or an earlier provider expiry. Marketapp can revoke it sooner. A remembered login shows **Connected** with **Disconnect** inside these collapsed connection details. Connection status does not mean the displayed report has refreshed. Disconnect removes the saved login without removing analytics. A wallet change invalidates it. Wallet proofs and signatures are never stored or replayed; the separate wallet connector stays in memory and leaves the ordinary dashboard wallet connection alone.

Without a remembered login, every refresh requires a fresh approval from the saved mainnet wallet. Closing Overview or reloading cancels the pending approval; a request already sent may finish. Start again if the five-minute approval expires. All analytics refreshes share the existing one-minute cooldown and five-per-hour allowance with connection tests. Wallet-approved refreshes make at most three website requests; remembered refreshes make one analytics GET. No automatic authentication retries or collection API requests are added. An expired/rejected session asks for a new approval on your next explicit refresh; network errors and changed analytics markup retain the remembered login and previous snapshots.

Each fresh Telegram app opening also checks whether analytics need updating, after the known-gift refresh has settled and the page is visible. It uses only an already remembered login and refreshes one period: the latest saved annual snapshot, or 30 days when no annual snapshot is current. Recent validated refreshes are reused for 15 minutes. The backend also enforces a 15-minute pause after an attempt, including failure, to prevent repeated openings from making repeated website requests. Concurrent openings share the website lease; busy work, request limits, missing login, and expired login leave saved analytics visible. Overview shows a compact update status. Automatic refresh never opens a wallet approval, scans gifts, or spends Marketapp API collection allowance. Manual **Refresh analytics** retains its existing limits and can request either supported period.

This uses Marketapp's website integration rather than a documented analytics API. Login rejection, wallet mismatch, missing/changed HTML, inconsistent totals, redirects, and timeouts leave earlier analytics available. A successful wallet connection alone is not a successful refresh: the backend requires Marketapp to accept the proof and return the saved wallet's requested daily period. A wallet-approved annual refresh has been verified in the private Telegram app. Remembered-session duration is controlled by Marketapp and has no guaranteed lifetime.

Returning from the wallet or reopening Overview checks the last refresh result from the private backend without requesting a new approval or contacting Marketapp. An update already sent can finish while the app is in the background. Failed results keep their fixed `MA-…` code visible; if status cannot be read, **Check status** reloads only saved progress. A saved result is confirmed against the exact committed snapshot. Only fixed stages, timestamps, booleans and an internal snapshot fingerprint are retained for this check, never login data or website HTML.

Marketapp's **Rent duration** histogram is recognised separately from the daily financial charts. Its duration categories do not supply dates or values for the saved daily statistics. Separate income/count charts and the observed combined activity chart are supported; ambiguous layouts, missing daily data, inconsistent totals and unknown chart types still fail validation.

## Capture and update on desktop

1. Open **Overview → Update analytics** and open your Marketapp analytics page in a normal browser where you are signed in to Marketapp.
2. Select **Rent**, **all collections**, the desired reporting period, and **By Day**. Daily source values are needed to build weekly, monthly, and calendar-year charts. To capture annual statistics, choose Marketapp's **1 year** reporting period before capturing. The app accepts up to 366 consecutive daily dates; this is independent of the 90-day comparison-history collection limit.
3. Use the capture bookmarklet supplied by the dashboard. Save it as a browser bookmark, with the copied `javascript:` code as its URL, and run that bookmark on the analytics page. The browser downloads `marketapp-rent-analytics-YYYY-MM-DD.json`. Browsers may remove `javascript:` when pasting into the address bar; saving a bookmark avoids that problem.
4. Return to Overview and choose **Import snapshot**. Select the downloaded JSON file. Importing it in the desktop app stores it locally. Importing it in the private Telegram app sends it to that app's private backend. The two stores remain separate.

To refresh through browser import, capture a new snapshot from the signed-in Marketapp page and import it again. Normal saved-data polling only reloads snapshots; Telegram's separate startup check can refresh analytics using a remembered login as described above. Desktop keeps browser capture/import. The capture code reads visible metric tiles and chart data attributes. It does not read cookies, wallet proofs, API keys, browser storage, or the rest of the account page, and makes no network requests of its own. Loading the Marketapp page still uses Marketapp's website normally.

The **Report period** selector uses separately saved snapshots, captured in the browser or refreshed in Telegram. Save both **30 days** and **1 year** to switch between their source totals. Changing chart grouping only changes the breakdown within that saved period. It does not fetch a longer period. The newest capture for each period length is available, up to eight saved lengths; exact dates and capture time are shown. A 366-day browser capture remains a distinct saved report from the 365-day wallet refresh. Older snapshots remain stored. Shorter-period distinct items and duration averages are not calculated from an annual snapshot.

The source must be a Marketapp rental analytics page for the dashboard's saved wallet. Address aliases are compared by canonical mainnet TON identity. Collection-filtered captures, aggregated charts, malformed files, inconsistent totals, and mismatched wallets are rejected. An unsuccessful import leaves existing analytics in place. Manual captures are user-supplied snapshots. Telegram refresh additionally verifies the website login and page wallet/period; neither workflow is an on-chain payment attestation or ownership proof.

## Meaning of the figures

- **Rent volume** is the amount renters paid for your items during the captured period, in GRAM, **before marketplace fees and royalties**. It is not net proceeds received, wallet balance, or lifetime revenue.
- Volume displays to one decimal in the total, chart labels and breakdown table. Exact source amounts remain stored and grouping uses their full precision. Gift asking prices and recommendations retain three decimals.
- **Rentals** includes new rentals and extensions. Their counts are also available separately. **Rented items** is Marketapp's distinct-item count for the entire captured period; it cannot be reconstructed or subdivided from daily aggregate counts.
- **Price per day** is Marketapp's rent volume divided by rented days. The app retains that reported aggregate; it does not average the daily rates. Reported average duration, extension share, and spending remain separate metrics.
- Daily volume and counts are summed for weekly buckets starting Monday, calendar months, and calendar years (January 1–December 31). The first and last bucket may cover only part of a week, month, or year. **By year** is a calendar-year chart grouping, while **Last 1 year** is the rolling reporting period for its summary. A 365-day rolling capture can span two partial calendar-year bars; their combined volume covers the saved reporting period. No missing months are projected and overlapping snapshots are never added together. The capture day may still be in progress. All period dates and grouping use UTC.
- Zero volume or counts remain zero. Missing optional values remain unknown. Money is retained as decimal text and summed exactly at the provider's supplied precision; chart values themselves may already have been rounded by Marketapp. The period volume preserves Marketapp's reported tile value. Daily sums must reconcile after rounding to that tile's precision, with at least two decimal places; rental counts must agree exactly. Small differences in the final decimals can therefore remain between a reported period volume and grouped chart totals.

The displayed period and capture timestamp accompany the saved figures. The source can include rentals of gifts that you no longer own. A finite reporting period does not establish lifetime income. No daily distinct-item count or net revenue is invented from the available aggregates.

In Telegram, press or tap a chart bar to show its UTC period, GRAM volume and rental count, including extensions. Drag horizontally across the chart to inspect nearby periods. Values remain visible after lifting your finger; tap outside, start scrolling, or change grouping to dismiss them. Mouse hover and keyboard arrow keys, Home, End and Escape also work. The tooltip reads saved data and makes no provider requests.

## Storage and access

Snapshot imports are limited to 256 KiB. Raw capture JSON and normalized data are retained as immutable snapshots, scoped to the saved wallet. Reimporting identical data is idempotent. Importing an older capture does not replace a newer one. Original Marketapp collection records and their fingerprints are unchanged.

If a private Telegram refresh cannot save because the database is full, it may discard rebuildable dashboard projections and retry the same guarded insert once. Reports and source evidence are retained. If space remains unavailable, saved analytics stay visible and no automatic retry loop starts.

The desktop import endpoint is loopback-only and requires the dashboard's same-origin/CSRF protection. It can import and display snapshots while provider networking is disabled. Telegram imports and refreshes require the private app's existing owner authorization. Login endpoints accept a freshly issued encrypted envelope and bounded wallet approval; remembered refresh accepts only a supported reporting period. Neither accepts user-supplied website cookies or arbitrary URLs. The documented Marketapp API GET allowlist is unchanged. Snapshots contain extracted analytics only; remembered cookies live in a separate encrypted backend table and never appear in snapshots, exports, browser storage or frontend assets. Authenticated HTML, proofs and wallet state-init are discarded.

Personal snapshot downloads, local databases, and exports are private operational data. `marketapp-rent-analytics*.json` is ignored by Git. Keep snapshots outside source folders and do not add them to test fixtures or releases. Tests use synthetic data.
